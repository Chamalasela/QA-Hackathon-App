Section 4: Event Lead Speaking Scripts

Kickoff (0:00)

"Welcome everyone to the QA Hackathon 2026! Today you'll be testing the MediCare Clinic system — a clinic appointment and patient management application. The app is already running centrally — just use the URL on your quick-reference card and select your team number to log in. Your goal is to find bugs, write test cases, and build automated UI tests — all using AI tools to work smarter and faster.

Quick reminders: You have 90 minutes. Templates cannot be modified — only add data. Submit to the shared folder before time runs out. Any AI tool is fair game. Organizers help with access issues only. Let's see which team can leverage AI most effectively!

Any questions before we start? ... Great. Your time starts NOW!"

Time Warnings

At 50 min remaining: "Quick update: 50 minutes remaining. You're about halfway. Make sure someone on your team is thinking about automation and the demo presentation."

At 30 min remaining: "30 minutes left! Start wrapping up your testing and focus on finalizing your deliverables. Make sure your CSVs are saved and your automation tests run."

At 10 min remaining: "10 minutes! Start copying your files to the submissions folder. Make sure bug-report.csv, test-cases.csv, and your automation folder are all there."

At 5 min remaining: "5 minutes! Submit now if you haven't. Start filling in your PPT for the demo."

At TIME: "Time is UP! Please stop working and submit your final files. You have 2 minutes to finish copying, then we break for demos."

Section 5: Troubleshooting Playbook

IssueSolution
Team can't access app URL 1. Check Wi-Fi connection on their device
2. Try from a different browser
3. Verify URL is correct (no typos)
4. Check if corporate proxy/VPN is blocking — disconnect VPN
Login fails with correct credentials Ensure team is selecting the correct Team number (1-6) on login page.
Verify password: Test@123 (case-sensitive)
App is slow or unresponsive Check server health: curl {APP_URL}/api/health
If server is down, restart the backend process on the host machine:
cd app/backend && node src/index.js
Swagger page is blank Direct URL: {APP_URL}/api-docs
Try hard refresh (Ctrl+Shift+R)
Team needs to reset their data Re-seed a specific team's database on the server:
cd app/backend && node -e "const {initDb,getDb}=require('./src/models/database'); initDb(N).then(()=>console.log('Done'))"
Or re-run full seed: node src/seed.js
Shared submission folder not accessible Fallback: teams email their CSVs to Evaluation Lead, or submit via USB drive.

Section 6: During the Hackathon — Do's and Don'ts

✅ DO

  • Help with app access/connectivity issues immediately
  • Announce time at 50 min, 30 min, 10 min, 5 min marks
  • Verify submissions are in the correct folder structure
  • Monitor the support channel and respond to access questions
  • Keep energy up — this should be fun!
  • Take photos/record demos (with permission) for post-event sharing

🚫 DON'T

  • Give hints about what bugs exist or where to look
  • Help with test case writing, automation code, or testing strategy
  • Allow template column modifications — explain that eval scripts depend on exact names
  • Give one team more setup time than others
  • Share the master bug list with anyone before the event ends
  • Let demos run over 10 minutes — be strict
If a team asks for testing hints: "We can only help with access or connectivity issues. Your testing strategy and bug-finding approach is part of the challenge. Try using AI tools to help you think of scenarios!"

Section 7: Evaluation Procedure (Step by Step)

Immediately After Submissions Close

  1. Verify folder structure for each team:
    submissions/
    ├── team-1/
    │ ├── bug-report.csv ← Required
    │ ├── test-cases.csv ← Required
    │ └── automation/ ← Required (folder with tests + README)
    ├── team-2/
    │ └── ...
    └── team-6/
  2. If any team is missing files, notify them immediately (they may have submitted to wrong path)

During Demo Phase (run in parallel)

  1. Run bug evaluation:
    python evaluate-bugs.py --submissions-dir ./submissions --master ./master-bug-list.json --output ./results/bugs-scores.json
  2. Run test case evaluation:
    python evaluate-testcases.py --submissions-dir ./submissions --master ./master-test-scenarios.json --output ./results/testcases-scores.json
  3. Run automation evaluation:
    python evaluate-automation.py --submissions-dir ./submissions --output ./results/automation-scores.json

    Note: This attempts to install deps and run each team's test suite. May take 5-10 min.

After Demos Complete

  1. Judges enter their demo scores (1-10 per category) into judging/scorecard.xlsx
  2. Generate final scoreboard:
    python generate-scoreboard.py --bugs ./results/bugs-scores.json --testcases ./results/testcases-scores.json --automation ./results/automation-scores.json --judges ./judging/scorecard.xlsx --output ./results/final-scoreboard.html
  3. Open final-scoreboard.html on projector for results announcement
Fallback: If evaluation scripts fail, manually review CSVs against the master bug list spreadsheet. Score: 10 points per exact match, 5 per partial, weighted by severity (Critical ×3, High ×2, Medium ×1.5, Low ×1).

Section 8: Judge Briefing Notes

Share this with judges before the event. They score the Demo & Strategy (15%) and AI Tool Usage (10%) categories.

Scoring (1-10 per criterion, per team)

Criterion1-3 (Poor)4-6 (Average)7-8 (Good)9-10 (Excellent)
Strategy Clarity No clear plan, chaotic Basic plan, some structure Clear division, logical approach Exceptional planning, clear rationale
AI Tool Effectiveness Barely used AI, or used for one trivial thing Used AI for 1-2 tasks Used AI across multiple tasks effectively Creative/innovative AI usage across all tasks
Communication Unclear, over time, disorganized Basic presentation, within time Clear, engaging, within time Exceptional clarity, demos work, polished
Teamwork Evidence One person did everything Some collaboration visible Clear role division, good coordination Seamless teamwork, everyone contributed
Innovation Standard approach only One creative element Multiple creative approaches Outstanding creativity, unique methods

What to Watch For During Demos

  • Did they divide roles smartly or did everyone do the same thing?
  • Did they use AI for MORE than just one task? (Best teams use AI for test cases, automation code, bug analysis, data generation, reporting)
  • Did they show automated tests actually running and passing?
  • Did they stay within 10 minutes?
  • Did multiple team members present or just one?

Bonus Nominations

Judges may nominate teams for special awards:

  • Best Bug Hunter — Found the most/highest-severity bugs
  • Most Creative AI Usage — Most innovative application of AI tools
  • Best Automation Suite — Most comprehensive, well-structured automation
  • Best Presentation — Most engaging, clear demo

Section 9: Contingency Plans

ScenarioActionWho Handles
Team can't access the app Check Wi-Fi, browser, URL. Try different browser/device. If server-side issue, restart backend on host machine. Tech Support Lead
Network/Wi-Fi goes down App is centrally hosted so teams need network access. If Wi-Fi is down: troubleshoot router, try mobile hotspot as backup. Pause timer if outage affects all teams equally for more than 5 min. Event Lead + Tech
Evaluation scripts fail Use manual backup: review CSVs against master bug list spreadsheet. Manually count matches. Score using simplified formula. Evaluation Lead
Team submits wrong format/path Evaluation Lead fixes in place before running scripts. Notify team. Evaluation Lead
Demo runs over 10 minutes Warn at 8 min ("2 minutes left"). Hard cut at 10 min ("Thank you, time's up"). No exceptions. Event Lead
Team member absent Team continues with remaining members. No rebalancing. Event Lead
Shared folder not accessible Fallback: teams email their CSVs to Evaluation Lead, or submit via USB drive. Tech Support Lead
Power outage If brief: pause timer, resume after power restored (same remaining time for all). If extended: reschedule. Event Lead

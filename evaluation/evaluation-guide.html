📊 Evaluation Guide

Step-by-step instructions for collecting team submissions and running automated evaluation

Step 1: Collect Team Submissions

At the end of the hackathon (90 minutes), each team submits their deliverables. They can either:

  • Option A: Drop files directly into their team folder on the shared drive/USB
  • Option B: Email/upload a ZIP file which the organizer extracts into the team folder

Expected Folder Structure

submissions/ ├── team-1/ │ ├── bug-report.csv ← Bug report (required) │ ├── test-cases.csv ← Test cases (required) │ └── automation/ ← Automation scripts folder (required) │ ├── test_login.py ← (or .js/.ts files) │ ├── test_patients.py │ └── ... ├── team-2/ │ ├── bug-report.csv │ ├── test-cases.csv │ └── automation/ ├── team-3/ ... ├── team-4/ ... ├── team-5/ ... └── team-6/ ...

Required File Names

DeliverableExpected NameFormat
Bug Reportbug-report.csvCSV with headers matching the template
Test Casestest-cases.csvCSV with headers matching the template
Automation Scriptsautomation/ folderAny .py, .js, or .ts files inside
Presentationpresentation.pptx (optional for eval)PowerPoint (judged live, not auto-scored)
⚠️ Important: File names must be exact: bug-report.csv and test-cases.csv (lowercase, with hyphens). The evaluation scripts look for these specific names. If a team uses different names, rename them before running evaluation.

Step 2: Verify Submissions

Before running evaluation, quickly verify each team's submission:

  • ✅ bug-report.csv exists and has the expected column headers
  • ✅ test-cases.csv exists and has the expected column headers
  • ✅ automation/ folder exists and contains at least one script file
  • ✅ CSV files are not empty (have data rows beyond the header)

Expected CSV Headers

bug-report.csv:

Bug_ID,Title,Module,Category,Severity,Steps_To_Reproduce,Expected_Result,Actual_Result,Screenshot_Path,Tool_Used

test-cases.csv:

TC_ID,Module,Title,Category,Priority,Preconditions,Steps,Expected_Result,Test_Data,Tool_Used

Step 3: Run Automated Evaluation

The evaluation scripts are in the evaluation/ folder. You need Python 3.8+ installed.

Option A: One-Click (Recommended)

Double-click run-evaluation.bat in the project root folder.
This will run all evaluations for all teams and generate the scoreboard automatically.

Option B: Manual Commands

cd evaluation

:: Evaluate bug reports (all teams)
python evaluate-bugs.py --all

:: Evaluate test cases (all teams)
python evaluate-testcases.py --all

:: Evaluate automation scripts (all teams)
python evaluate-automation.py --all

:: Generate final scoreboard (after manual scores are added)
python generate-scoreboard.py

Evaluate a Single Team

python evaluate-bugs.py --team 3
python evaluate-testcases.py --team 3
python evaluate-automation.py --team 3

Step 4: Manual Scoring (Demo & AI Usage)

The automated scripts handle Bugs (300), Test Cases (250), and Automation (200). The remaining categories are scored by judges:

CategoryMax PointsHow to Score
Demo & Strategy150Judge fills out judge-scorecard.html during team presentations
AI Tool Usage100Judge evaluates AI usage claims during demo Q&A
Bonus50Judge awards for exceptional work

Saving Manual Scores

  1. Open materials/judge-scorecard.html in a browser
  2. Select the team from the dropdown
  3. Fill in scores for each criterion
  4. Click "Export as JSON"
  5. Save the downloaded file (team-N-manual.json) into the judging/ folder

Step 5: Generate Final Scoreboard

After all automated evaluations AND manual judge scores are in the judging/ folder:

python evaluation/generate-scoreboard.py

This produces:

  • judging/final-scoreboard.json — Machine-readable results
  • judging/scoreboard.html — Beautiful HTML scoreboard to display on screen
  • Console output with rankings
💡 Tip: Open judging/scoreboard.html in a browser and project it on screen for the awards ceremony!

After running evaluation, the judging/ folder will contain:

(repeat for all teams) ├── bugs-summary.json ← All teams' bug scores ├── testcases-summary.json ← All teams' test case scores ├── final-scoreboard.json ← Final combined scoreboard └── scoreboard.html ← Display-ready HTML scoreboard
